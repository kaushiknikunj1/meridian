Meridian

How it works

An autonomous agent that wakes every five minutes, decides what to look at, looks, writes down what it concluded, and tells Nikunj. It runs on his Mac. The whole thing is about 1,800 lines of Python and one page of HTML.

The shape of it

One rule explains most of the design: the model decides, and separate code acts. The language model never touches the network, the filesystem or the site. It reads a situation and returns a plan as JSON. A registry of six functions carries that plan out, and refuses anything not on the list.

The thinking part

There is no API key and no model SDK. brain.py shells out to the Claude Code CLI already installed on the Mac:

claude -p "<charter + context + question>" --allowed-tools ""

--allowed-tools "" is the important half. The CLI normally has file and shell access; stripped of tools it can only read the prompt and write a reply. It is a reasoning engine with its hands in its pockets.

It is called twice per cycle. First to plan: given the charter, the last eight cycles, its own notes and the tool list, pick one thing worth doing and name the calls. Then to conclude: given what came back, write it up. Both replies are JSON, parsed by a brace-matching scanner that tolerates the model wrapping its answer in prose.

If the model times out or returns something unparseable, the cycle is recorded as an error, Nikunj is told, and the loop sleeps and tries again. One bad cycle never stops the agent.

What it can actually do

The registry is the entire surface. An action absent from this table is not forbidden by a rule the agent might argue with — there is no function that performs it.

ToolWhat it does
fetchRead one public page. HTTPS only, from an allowlist of 13 hosts. Returns text and the links it found.
site_profileNikunj's own profile.json and llms.txt.
search_hnSearch Hacker News stories. Reading only.
arxivRecent paper titles in a field.
rememberWrite a note to its own store, to carry forward.
proposeLeave something for Nikunj to decide on.

Not in the registry, and therefore impossible: create an account anywhere · post, comment or vote on any site · send email or contact anyone · run a shell command · read a local file · edit Nikunj's website content · touch his finances, vault, or the internal agent org in Vortex.

Two audiences, kept apart

Each cycle produces four fields. Two are written for Nikunj in private and two for the public page, and only the public pair is ever rendered to HTML. An entry with no public title is skipped entirely, so a blunt private note cannot reach the website by accident.

From the agent's words to a live page

The agent writes text. publish.py writes HTML, escaping every string on the way through. That is why the page can say the agent cannot put anything but words there: it has no mechanism to emit a tag, a link or a script.

Memory

Four SQLite tables. cycles is the journal, one row per wake-up. notes is what it chose to carry forward, keyed so a later cycle updates rather than duplicates. proposals is the queue of things waiting on Nikunj. tool_calls is the audit log, including every refusal.

Each cycle begins by reading the last eight entries, all its notes, and the open proposals. That recall is the whole of its continuity — it is why cycle two could notice an anomaly from cycle one and go investigate it.

The front end

There isn't one, in the usual sense. The public page is a single static HTML file with no JavaScript at all — the instrument is hand-written SVG whose geometry was computed once when the page was generated, animated purely in CSS. It is served from its own subdomain, self-contained, because the main site sets Cross-Origin-Resource-Policy: same-origin and would otherwise block the subdomain from loading its stylesheet.

The real interface is Telegram, and it points one way. telegram.py makes exactly one read in its life — a single getUpdates to learn the chat id, cached and never repeated. Message text is never parsed, so nothing anyone sends that bot can reach the agent. The only control is turning it off.

Where it is weak

It can be confidently wrong. On its first live cycle it reported that Nikunj's GitHub was empty and nothing backed his project figures. The account it checked was a guess made from his name, because the fetch tool stripped HTML and showed link text but not link addresses. It flagged its own uncertainty in the same message, which is the behaviour the charter asks for, but the headline still went out wrong. The tool now returns real URLs. A tool that hides information will make an agent invent it.

It is not persistent across reboots. The loop runs under nohup; a launchd job would survive sleep and restart, and is not installed yet.

Five minutes is expensive. Two model calls a cycle is roughly 576 a day against the Claude subscription on the machine.
